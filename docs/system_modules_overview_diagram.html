Chapter 2 / System Architecture: System Modules & Multi-Tier Topology

The software architecture of the SSG Office Assistant Application at Cebu Technological University – Daanbantayan Campus is structured as a decoupled, multi-tier system engineered around the foundational principles of Separation of Concerns (SoC), High Availability (HA), and Zero-Trust Client-Side Routing.

1. Tier 1: Client Presentation & Role-Based Ingress Layer

The presentation tier is constructed using React 18, Vite, and React Router DOM v6. Rather than allowing unrestricted client-side component loading, all sensitive administrative portals are wrapped inside a unified ProtectedRoute gate.

  • Role-Based Access Control (RBAC): The client enforces privileges across eight standardized institutional roles: (1) General Students, (2) Creative Team, (3) House Representatives, (4) Governors, (5) Legislative Branch, (6) President, (7) Budget Sector, and (8) System Administrators.
  • Cryptographic Token Validation: Every routing request evaluates the user’s Firebase ID Token, extracting cryptographically signed Custom Claims and in-memory permission overrides without exposing underlying API keys.

2. Tier 2: Core Functional UI Modules

The application is partitioned into six decoupled functional modules, each encapsulating discrete domain logic:

  • Module 1 · User & Identity Management: Controls user registration, administrative role promotion/demotion, self-demotion shields, and account activation flags.
  • Module 2 · Member Management: Orchestrates bulk student roster uploads via PapaParse (CSV/XLSX), class Mayor verifications, and department-based directory filtering across all 7 recognized campus organizations.
  • Module 3 · Product, Commerce Hub & Order Management: Manages SSG official uniforms and merchandise inventories with automatic stock decrementing, public order tracking by order ID/email, and equipment borrowing checkouts.
  • Module 4 · Financial Tracking & Fiscal Management: Maintains immutable double-entry style income and expense ledgers, Death Aid remittances, digital receipt attachments, and automated liquidation PDF report generation.
  • Module 5 · Document Management Repository: Archives legislative resolutions, executive memos, and committee policies tagged by author, term, and committee with in-browser binary streaming.
  • Module 6 · Communications Gateway: Formats rich broadcast announcements, synchronizes the academic calendar widget, and routes automated webhook notifications to the Telegram Bot API.

3. Tier 3: Hybrid Cloud Persistence & AI Parsing Infrastructure

To balance low-latency transactions with massive binary document archiving, the backend employs a hybrid persistence model:

  • Firebase Auth & Cloud Firestore: Acts as the real-time NoSQL state synchronization engine for transactional collections (users, classRosters, products, orders, finances), supported by Firestore Security Rules.
  • MongoDB Atlas GridFS Engine: Operates on an independent database (ssg_documents) and bucket (documents.files / documents.chunks) accessed through a Node.js Express REST proxy. By chunking large resolution PDFs and receipts into 255KB binary blocks, the system completely bypasses cloud storage plan limitations with zero memory leaks.
  • AI Document Parsing Pipeline: Connects directly to GridFS memory buffers. Utilizing a failover chain from Google Gemini 1.5/2.5 Pro to OpenRouter, the pipeline parses document text, extracts authors and resolution numbers, and assigns committee tags under a strict 15 req/min client-side rate limit.
