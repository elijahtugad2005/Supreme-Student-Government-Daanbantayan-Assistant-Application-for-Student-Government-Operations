⚡ Chapter 2 — System Architecture

Telegram Bot Integration Architecture

Secure event-driven broadcast gateway bridging Supreme Student Government (SSG) announcements with real-time external subscriber channels (CTU-DB Faculty & Mayors Channels).

TIER 1: PRESENTATION & COMPOSITION (CLIENT SPA)
📢

Officer Broadcast UI

Announcement.jsx
  • Officer composes campus release
  • Selects category (Event, Memo, etc.)
  • Selects channel destination
  • Optional image attachment (Base64)
⚙️

Channel Resolution

announcementTypes.js
  • Resolves single or fanned destinations
  • Pairs type emoji + formal header
  • Applies clean HTML markup styling
  • HTML-escapes officer inputs
🛡️

Security & Redaction

telegramService.js
  • Validates token & channel ID presence
  • Token regex scrubbing on error dumps
  • Prevents token leakage in client errors
  • Builds inline callback reaction markup
🌐

Payload Dispatch

Fetch API / HTTPS
  • POST /sendMessage (HTML text)
  • POST /sendPhoto (Multipart binary)
  • Saves message_id to Firestore record
  • Handles 48h lifecycle message deletion

🔒 Token Redaction & Sanitization
Client-side regex scrubbers strip credentials from network stack traces and error logs so API keys can never be exposed in browser consoles or failed request dumps.
⚡ Fan-Out Multicast Broadcasting
A single officer announcement can simultaneously fan out to separate Telegram channels (Faculty & All Mayors) with independent delivery tracking and message identifiers.
🔄 Bi-Directional Message Lifecycle
When an announcement is updated or removed in the SSG dashboard within 48 hours, the system invokes deleteMessage on Telegram to prevent outdated campus misinformation.
