1. Phase 1: Cryptographic Challenge-Response Verification (GET /webhook)

Before any external event broker dispatches updates to the server, a mutual handshake is required to verify ownership of the callback URL:

  • The Ingress Handshake Trigger: The external platform sends an HTTP GET request to /webhook carrying three mandatory query parameters: hub.mode=subscribe, hub.verify_token=<token>, and hub.challenge=<random_int>.
  • Server-Side Secret Evaluation: The Express gateway validates whether hub.mode === 'subscribe' and verifies that the provided token strictly matches process.env.VERIFY_TOKEN stored securely in the server environment.
  • Deterministic Decision Outcomes:
    • Path A (Verified): If the token matches, the server returns an HTTP 200 OK response containing the exact hub.challenge string as plaintext, confirming endpoint authenticity.
    • Path B (Forbidden): If the token is invalid, missing, or mismatched, the server rejects the request with an HTTP 403 Forbidden status, aborting the registration attempt and logging a security warning.

2. Phase 2: Asynchronous Event Dispatch & Broadcasting (POST /webhook)

Once verified, the backend operates as a high-speed event dispatcher bridging database transactions with subscribed campus stakeholders:

  • Database Event Trigger: An authorized SSG Officer publishes an announcement, circular, or calendar reminder in the React client. The event commits to Firestore (announcements collection).
  • Webhook Ingress & Rapid Acknowledgment: The event payload reaches the Express POST /webhook endpoint. Following microservice best practices, the server immediately returns a 200 OK ('EVENT_RECEIVED') acknowledgment to avoid HTTP timeouts, then pushes the payload into an in-memory asynchronous worker queue.
  • Audience Resolution & Formatting: The background worker queries the faculty_subscribers collection in Firestore to retrieve verified Telegram chat_id identifiers for campus advisers, department chairs, and faculty representatives. The payload is parsed into clean HTML markup with inline action buttons (e.g., "❤️ Acknowledge / Seen").
  • Telegram Bot API Dispatch: The backend dispatches HTTP POST requests to https://api.telegram.org/bot<BOT_TOKEN>/sendMessage. The secret token remains isolated in the server environment and is never exposed to client browsers.

3. Elimination of Institutional Information Silos

Historically, CTU – Daanbantayan student government announcements relied on casual Facebook Messenger group chats where critical academic directives were frequently submerged beneath informal discussion. This event-driven webhook architecture eliminates institutional silos by:

  • Ensuring university advisers and department faculty receive real-time, tamper-resistant push alerts simultaneously with the student body.
  • Providing verifiable read-receipt callbacks to record exactly when faculty advisers acknowledged official student government circulars.
