Chapter 2 / Integration Plan: Facebook Messenger Architecture Specification

The SSG Office Assistant App at Cebu Technological University – Daanbantayan Campus incorporates an automated Facebook Messenger integration plan. While the current operational model relies on informal, personal Messenger group chats that suffer from lost directives and communication silos, the proposed architecture establishes an enterprise-grade, bidirectional bridge using the Meta Graph API and Webhook Event Protocol.

1. Four-Tier Communication Topology

  • Tier 1 · SSG Administrative Client (React SPA): Authorized officers compose official announcements within the Announcement Module, attaching category metadata and action buttons. The client sends authenticated payloads to the backend without directly exposing Page Access Tokens in the browser.
  • Tier 2 · Secure Backend Gateway & Webhook Gateway (Express.js): Implemented in backend/server.js:
    • Outbound Proxy: Signs requests with the secret PAGE_ACCESS_TOKEN and enforces dispatch pacing.
    • Verification Handshake (GET /webhook): Validates hub.mode === 'subscribe' and matches hub.verify_token === VERIFY_TOKEN, returning the challenge to establish webhook subscription.
    • Ingress Webhook (POST /webhook): Instantly acknowledges incoming message events with an HTTP 200 OK (meeting Meta's strict 3-second SLA) before offloading payload handling to an asynchronous processing queue.
  • Tier 3 · Meta Cloud Platform (Graph API & Webhook Broker): Dispatches rich message templates (carousels, quick replies, images) to subscribed student endpoints and forwards inbound student messages to the campus server.
  • Tier 4 · Student Body & Campus Organizations (Messenger Mobile/Desktop): Students receive official campus memos directly within their native Messenger application, interact via quick-reply buttons (e.g., "Check Order Status", "View Guidelines"), or submit inquiries.

2. Privacy & Data Security Compliance

The integration leverages Page-Scoped IDs (PSID). A student's interactions generate a distinct PSID that cannot be cross-referenced with outside Facebook accounts, preserving student data privacy in compliance with the Data Privacy Act of 2012 (RA 10173). Inbound queries are stored in Firestore (inquiries/{psid}) to enable real-time operator ticket handling while shielding the university from spam and phishing risks.
